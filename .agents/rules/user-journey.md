The primary StackAudit user journey should follow this direction:

Developer
→ Understand developer skills
→ Discover suitable repositories
→ Evaluate repository suitability
→ Find suitable issues
→ Match developer with issues
→ Understand relevant code
→ Identify relevant files/modules
→ Understand what needs to change
→ Receive contribution guidance
→ Make the contribution

Do not make "Analyze Repository" the primary user objective.
