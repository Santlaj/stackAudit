STACKAUDIT UI DIRECTION

StackAudit is a developer infrastructure/code-analysis product.

The UI must look like a product built by an experienced
product design + frontend engineering team.

VISUAL REFERENCES:

- Linear
- GitHub
- Vercel
- Sentry

These are references for information hierarchy, density,
navigation and interaction patterns only.
Do not copy their branding or layouts.

DO NOT USE:

- centered hero layouts
- generic SaaS landing-page layouts
- giant headings
- gradient backgrounds
- purple/blue AI gradients
- glassmorphism
- glowing cards
- excessive rounded cards
- floating blobs
- oversized empty whitespace
- every section centered
- "AI-powered" visual clichés
- unnecessary illustrations
- decorative UI that does not communicate information

LAYOUT:

- Prefer left-aligned content.
- Use asymmetric layouts where appropriate.
- Use a persistent sidebar for application pages.
- Use compact top navigation.
- Prefer information-dense layouts appropriate for developers.
- Establish a strong 8px spacing system.
- Use a clear content grid.
- Keep primary actions close to the content they affect.
- Use horizontal structures where they improve information density.

TYPOGRAPHY:

- Strong hierarchy but restrained scale.
- Avoid enormous H1/H2 text.
- Body text should remain compact and readable.
- Use typography to establish hierarchy instead of cards and colors.

COLOR:

- Neutral foundation.
- One restrained accent color.
- Semantic colors only for status:
  success / warning / error / info.
- No gradients unless explicitly justified.

COMPONENTS:

- Use cards only when there is a real grouping boundary.
- Prefer tables, lists, tabs, panels and sections for developer data.
- Avoid putting every piece of information inside a card.
- Avoid excessive border radius.
- Avoid excessive shadows.

IMPORTANT:
Before implementing a page, determine:

1. What information the user needs first.
2. What action the user needs to take.
3. What information is secondary.
4. What can be represented as a table/list instead of a card.

The interface should feel like developer infrastructure software,
not an AI-generated SaaS template.
